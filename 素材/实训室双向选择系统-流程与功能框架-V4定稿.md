# 实训室双向选择系统 · 流程与功能框架（V4 定稿）

依据：① 学院官方海报《学生实训室进组选拔流程》（时间轴基准）② 用户手绘流程图 ③ 多轮讨论决策。
标注：〔海报〕〔原图〕【改】【补】【删】。
V4 变更：补录固定两轮；撤销宣讲/开放日/公示的系统功能（改为纯线下）；新增 7a 内部调剂完整机制（教师先接受+学生征求+拒一次出室）；调剂池定为"教师挑人+管理员兜底"；四维评分彻底删除；抽出通用"录取待确认"组件。

| 教师 | 登录（工号+教务核验）、个人简介与招生说明、报名学生列表（隐去志愿序号）、出三张名单、约谈时间发送、补录直接录入、空额与递补视图、**7a 接受/拒绝负责人指定的调剂生**、调剂池挑人抢录、本人名下学生查询 |
| 本室管理员（lab_scope=某室） | 本室场次与场地安排、本室三张名单审核、**执行 7a 内部调剂**、本室名额与录取总览、代录补空缺（不覆盖已提交内容） |
| 全院管理员（lab_scope=ALL） | 教务与基础数据导入维护、批次与全部时间窗配置（含补录两轮子窗、7a/7b/7c 三子窗）、教师名额上限、指定本室管理员、阶段内修改权（原因+日志）、剩余名额汇总公布、**调剂池管理员兜底分配**、约谈确认与直接指定安置、密码重置、统计图表、名单导出、重置/锁定、日志查询 |

线下环节（不做系统功能）：集中宣讲 10/28、实训室开放日 10/29–30、结果公示 1 天。

## 三、系统流程与时间轴

```text
S1 志愿填报        11/2 08:00–12:00      3 个平行导师意向 + 两个调剂勾选〔海报③〕
S2 面试初选        11/2 12:00–11/3 17:00  统一面试（全员参加，不筛人）→ 出三张名单〔海报④+D2〕
S3 拟录取与确认    11/4 08:00–12:00      1 个录取→自动确认；≥2 个→限时择一；逾期=放弃；实时递补〔海报⑤+D7〕
S4 第二轮补录      11/4 12:00 起          公布剩余名额 → 未录取者填1 志愿 → 面试或直接录入 → 确认与递补
S5 第三轮补录      ~11/5 17:00 止         **机制与第二轮完全相同**（组件复用）
S6 统筹调剂        11/6 08:00–12:00       三子阶段，时间窗均可配
   6a 内部调剂     负责人挑人→教师接受→学生征求→拒一次即出室【D17】
   6b 全院调剂池   教师挑人先抢先得录入 + 管理员兜底分配【D5】
   6c 约谈安置     管理员确认→线下约谈→管理员直接指定室【D13】
S7 锁定归档        生成录取情况单、导出名单、批次锁定
```

## 四、逐环节说明

### S1 志愿填报（11/2 08:00–12:00）

- 学生注册：学号+密码，校验教务数据是否存在该学号〔原图〕；不做开放自助注册，名单由管理员导入激活
- 填写个人简介〔原图〕
- 查看教师/实训室信息〔原图〕
- 最多 3 个**平行**导师意向，不分先后〔海报+原图〕→ 数据层**不设 priority 字段**
- 【补·D8】两个独立勾选：□服从实训室内部调剂 □服从全院跨实训室调剂
  - ‣ 全院项旁提示："服从全院调剂后由教师直接录入，不再二次确认"
- 【补】草稿暂存与提交锁定；提交前可反复修改，提交/截止后只读；唯一索引拦重复提交

### S2 导师初选与面试考核（11/2 12:00–11/3 17:00）

- 以实训室为单位统一面试；**无论报名是否满额，所有报名学生均参加**〔海报〕
- 面试排期发布与查看（场次、场地、面试官）【补】
- 四维评分录入【删·D14】四维度考察为线下要求，系统不留档
- 【改·D2】教师产出三张名单：拟录取 / 递补（有序顺位）/ 内部调剂候选
- 教师"发送线下约面信息"〔原图〕→ 站内通知；同一时段可约多人，超额提示
- 本室管理员：名单审核、代录补空缺（不覆盖教师已提交内容）

### S3 拟录取与学生确认（11/4 08:00–12:00）

- 仅收到 **1 个**拟录取 → 自动确认〔海报原文条件为"收到"，非"填报"〕；学生不可反悔
- 收到 **2 个及以上** → 窗口内自主择一〔海报+原图〕；其余 offer 自动释放并触发对应室递补
- 逾期未确认 = 视为放弃；**放弃 = 永久退出本批次竞争**，不可被任何室递补或再次申报
- 【D7】空额按顺位**实时递补**（规则见第五节）
- 12:00 **硬性切断**：仍在递补链上未决者按逾期放弃处理，空额计入补录剩余名额
- 管理员：阶段内可修改本阶段选择（手动确认/取消通过/改派），强制填原因+审计日志
- 【补】状态互斥：确认即锁定，自动解除其持有的其他待定 offer，不再进入任何递补序列
- **实现**：本页即通用"录取待确认"组件【D18】的第一个实例

### S4 第二轮补录（11/4 12:00 起）

- 补录开始前：管理员汇总并**公布各实训室剩余名额**〔原图缺失〕
- 【D9】学生只填 **1 个**志愿；可重复申报第一轮已面试过的室
- 流程与 S2/S3 一致〔海报〕：统一面试 → 教师确认/拒绝 → 双向确认与顺位递补
- 【D10】教师可选择直接录入（凭教师判断，免面试）
- 本轮结束存**轮次快照**（名单可回溯）；汇总剩余名额进 S5

### S5 第三轮补录（~11/5 17:00 止）【D3】

- **机制与第二轮完全相同**：同一套"公布余位→填1 志愿→面试或直接录入→确认与递补"组件，仅轮次编号不同
- 唯一区别：本轮结束后未录取者不再补录，按调剂勾选进入 S6
- 因组件复用，**新增这一轮的增量开发量很小**（主要是时间窗与数据表的 round 字段）

### S6 统筹调剂（11/6 08:00–12:00，三级优先级〔海报〕）

#### 6a 实训室内部调剂（优先级①）【D17 新增】

典型场景：学生 a 报的是本室教师 b，b 没录他（在 b 处落选），但 a 勾了"服从实训室内部调剂"，本室教师 c 尚有空额。

流程（四步，双向+学生确认三段式）：

```text
① 负责人从本室"内部调剂候选名单"挑中 a
② 指定给教师 c → c 端收到"接受/拒绝"请求（仅 c 名额未满时可指定）
③ c 接受后 → 向学生 a 发起征求（复用"录取待确认"组件），带时限
④ a 同意 → 扣减 c 名额、生成录取记录、通知各方，流程结束
   a 拒绝或逾期未响应 → a **永久出该室**（该室不得再次征求），转入 6b 或 6c
```

规则要点：

- **名额软占位**：c 接受后到 a 确认前，c 的名额标记为"待定占用"，不正式扣减——避免 c 被空置占额；a 确认才正式扣减
- **拒一次即出室**：同一室对同一学生只有一次征求机会，防同室反复拉锯拖满时间窗【本轮确认】
- **出室后去向**：勾了"服从全院调剂"→ 进 6b 池；只勾内部或未勾任何调剂 → 进 6c 约谈
- 若 a 同时是本室递补名单上的顺位生 → 递补优先，递补生效后自动移出调剂候选名单
- **逾期处理**：默认**视为不同意**（与 S3"逾期=放弃当前机会"口径一致，保持学生意愿优先），可在配置中改为"视为同意"

#### 6b 全院跨实训室调剂池（优先级②）【D5】

- 入池条件：三轮结束后未录取 + 勾选"服从全院跨实训室调剂"
- 入池前强制完善个人简介；池内仅展示简介〔D14 不展示初试结果〕
- **教师挑人**：浏览池内简介 → 按选择时间先后 → **直接录入即生效**，学生不二次确认
- 并发抢锁：后提交者失败，提示"该生已被 XX 实训室录入"【补】
- 池列表实时刷新、被录入者即时置灰移出；不设教师同时锁定上限
- 录入即扣减该教师名额、生成匹配结果、通知学生
- **管理员兜底**：教师挑剩（池内长时间无人问津）的学生，由全院管理员直接指定分配至仍有空额的实训室
- 池内最终仍有未分配者 → 转入 6c

#### 6c 未服从调剂者安置（优先级③）〔海报"约谈安置"】

- 对象：未勾任何调剂且仍未录取者 + 6b 池内最终未被挑走/未被兜底分配者
- 管理员手动逐个确认 → 向学生发送**线下约谈通知**
- 【D13】约谈后管理员**直接把学生改到指定实训室**并发送录取通知；无"保留待定/其他"终态
- 约谈台账留痕：学生、约谈人、安置去向、操作时间、原因

### S7 锁定归档

- 生成录取情况单〔原图〕、导出名单（学号/工号）〔原图〕、批次锁定
- 【D11】系统内不做公示、不展示他人名单；学生端只见本人结果；公示由学院线下完成
- 【补】每阶段结束输出扇形/柱状统计分析〔原图〕
- 【补】关键节点自动通知（录取、放弃、被调剂、约谈、入组）

## 五、实时递补规则（D7）

**有限性论证**：学生总数有限 + 递补名单顺位固定 + 放弃者永久出局 → 递补链沿有限名单单向推进，不存在无限循环。

| 规则 | 内容 |
|---|---|
| R1 触发源封闭 | 递补仅由"放弃 / 逾期未确认 / 多选一未选该室"三种事件触发 |
| R2 锁定制（=D1） | 确认即锁定，不再收递补通知；未选 offer 自动释放 |
| R3 保底窗 T=30min | 递补 offer 截止 = max(窗口截止, 通知时刻+30min)；截止仍未决按逾期放弃硬切断 |
| R4 offer 集实时刷新 | 多选一界面实时并入新递补 offer；提交瞬间并发修改用乐观锁/版本号处理 |

## 六、工程硬约束（D16，10 条）

1. 名额是唯一事实来源：由管理员录入，录取与扣减同事务
2. 服务端判时：阶段开关由服务端校验，不信前端时间
3. 轮次快照：每轮存快照，名单可回溯（补录两轮各自独立快照）
4. 并发写保护：调剂池抢录用唯一索引/乐观锁，避免双写覆盖
5. 唯一索引拦重复提交：志愿、offer 确认、调剂录入、征求响应均需幂等
6. 逾期扫描用定时任务：不依赖学生是否开着网页
7. 看板读库不缓存：名额余量、报名进度直接读库
8. 人工干预二次确认 + 全量审计：管理员阶段内修改必须填原因
9. 导出仅内部版（全字段，需二次确认）；【删】脱敏公示版，因不做系统内公示
10. 异常预警：未匹配名单、超发风险自动提示

## 八、边界情况清单（测试重点）

1. 未填任何志愿 → 直接落入 S6（按勾选状态归类）
2. 3 个志愿全部落选 → 按调剂勾选进 6a/6b/6c
3. 教师名额 0 或全部 reject → 该室不产生 offer
4. 递补学生同时持多个待确认 offer → R4 实时并入
5. 两人同时抢录同一学生 → 一成功一失败提示
6. 学生被录入瞬间其正处于补录确认/内部调剂征求中 → 状态互斥校验
7. 管理员阶段内修改导致某室超编/空缺 → 名额一致性自动校验
8. 截止时刻硬切断时仍在递补链上的学生 → 逾期放弃并计入剩余名额
9. 已放弃者被再次递补/申报 → 系统拒绝（永久出局校验）
10. **6a 软占位期间教师又录了别人导致满额** → 征求应自动失效并通知负责人
11. **6a 学生拒绝后同室再次发起** → 系统拒绝（拒一次即出室校验）
12. **6a 教师拒绝接受负责人指定** → 名额不变，负责人需另择教师或转入 6b
13. **学生同时在递补名单与调剂候选名单** → 递补优先，生效后移出候选
