# 安全契约（SECURITY）

> 教师/组长端的安全基线。部分能力依赖后端，前端只做“不越权、不泄露、可追溯”。

---

## 1. 身份与权限

- 角色：`STUDENT` / `LAB_TEACHER` / `LAB_LEADER` / `COLLEGE_ADMIN`；
- 前端路由守卫只做体验，**服务端必须重新校验**角色、实训室范围、阶段；
- 实训室范围以 token 中的 `laboratoryId` 为准，前端传参不得作为授权依据；
- 组长可访问教师功能；跨室数据一律不可见（除学院端）。

## 2. 数据可见性

- 本室教师只能看本室报名、面试、简历；
- 普通教师查看简历需填理由，会话内 30 分钟免重复，每次查看留痕；
- 其他室的评价、拟录取、调剂状态不可见；
- 学生确认结果由学院端统一汇总，不由本室推断。

## 3. 导出

- 组长：可导出本室全部；
- 普通教师：仅本人面试过的学生，CSV 首行水印 + 手机号脱敏；
- CSV 公式注入防护：以 `= + - @` 开头的单元格自动加 `'`；
- 导出成功/失败均写操作日志（`EXPORT` / `EXPORT_FAILED`）；
- Excel 导出由后端生成，前端 CSV 仅过渡。

## 4. 操作日志

- 关键动作：名单增补/移出、确认、放弃、调剂、提交、审核、导出、查看简历、排期、阶段/时间申请、规则/权重变更；
- 日志带 `prevHash + hash` 哈希链，页面显示“完整性：通过/异常/历史数据”；
- 前端日志可被清空，**不具备法律审计效力**；正式版必须后端写 `operation_logs` 并防篡改。

## 5. 文件与简历

- 简历 PDF 由学生上传，前端只预留位置，不批量生成假附件；
- 附件访问必须鉴权并校验范围；建议使用短期签名 URL；
- 禁止在文件名/路径中拼接用户输入。

## 6. 时间与阶段

- 系统时间固定并持久化，前端不提供改时入口；
- 需要调整只能由组长提交“时间变更申请”，学院端审批后由后端修改；
- 写操作按阶段左闭右开区间 + 上一阶段完成度校验；
- 截止后禁止手动确认/评价/调剂；到期结算由服务端幂等执行并保留快照。

## 7. 前端安全

- Vue 默认转义，禁止使用 `v-html` 渲染用户内容；
- 不在 localStorage 存密码/密钥；token 由公共模块管理；
- 多标签页通过 `storage` 事件同步，避免覆盖；
- 演示数据与真实数据必须通过环境变量/开关隔离。

## 8. 后端必须补齐（当前未实现）

- JWT 签发与刷新、Redis 黑名单；
- RBAC 数据范围校验、阶段中间件、幂等键；
- 请求限流、登录失败锁定、CSRF/CORS 白名单；
- 文件类型/大小校验与病毒扫描；
- 审计日志落库与只追加存储；
- HTTPS、密钥管理、日志脱敏。
