# 05 Rules｜规则、不变量与验收

> 版本：v1.0（阶段 1 定稿待确认）
> 本文档是 `01_PRD.md`、`03_Database.md`、`04_API.md`、`flow/` 的规则索引层。规则正文以各文档为准，本文档负责编号、汇总与验收。

## 1. 编号规则

| 前缀 | 含义 | 用途 |
|---|---|---|
| `INV-xx` | 全局不变量 | 任何时刻都必须成立，破一条即为严重缺陷 |
| `BR-Pn-xx` | 第 n 阶段的业务规则 | 开发实现依据，评审逐条勾 |
| `EX-Pn-xx` | 第 n 阶段的异常与边界 | 测试用例来源 |
| `AC-xx` | 验收标准 | 上线前放行清单 |
| `Q-xx` | 待确认问题 | 需业务方拍板，拍板后回写正文 |

一个判断标准：任何一条规则，若回答不了「属于哪个阶段 / 由谁触发 / 写哪张表 / 受哪个时间窗约束」，它就没有落到契约里。

## 2. 全局不变量 INV

| 编号 | 不变量 | 落点 | 违反后果 |
|---|---|---|---|
| INV-01 | 同一导师任意时刻 `quota_used ≤ quota` | `mentor_profile` 条件更新 | 超录，无法向学生交代 |
| INV-02 | 同一学生同一轮最多一条 `admission.status ∈ {2,3}` | `admission` + 业务层校验 | 一人多处，公示冲突 |
| INV-03 | 同一轮同一导师对同一学生最多一条 `admission` | `uk_round_mentor_student` | 重复占位 |
| INV-04 | 同一轮同一实训室同一学生只有一套评分 | `interview_score` 唯一键 | 本室分数不统一 |
| INV-05 | 同一学生同一轮只有一份填报 | `intention` 唯一键 | 志愿数据混乱 |
| INV-06 | 一份填报 1–3 条平行意向，表内无顺序字段 | `intention_item` | 变相引入第一志愿 |
| INV-07 | 四维权重合计恒为 `100.00` | `selection_round` 保存校验 | 总分不可比 |
| INV-08 | 单 offer 自动确认只发生在 `nomination_submit_end` 批次签发后 | 批处理流程 | 分批提交误判 |
| INV-09 | 未勾选对应级别调剂意愿的学生不得被自动分配 | 调剂前置校验 | 未授权分配 |
| INV-10 | 名额冻结后 `quota` 不可静默修改 | `mentor_profile` + `operation_log` | 学生基于假信息决策 |
| INV-11 | 公示名单不含分数、评语、作答、未录取者 | API 字段白名单 | 隐私泄露 |
| INV-12 | 每轮结束 `SUM(quota) = SUM(已确认) + SUM(剩余)` | 对账任务 | 名额对不上账 |
| INV-13 | 名额调整、顺位调整、调剂、异议处理必须写 `operation_log` | `operation_log` | 无法追溯 |
| INV-14 | 填报窗口内导师不可见任何报名名单；负责人仅可见本室聚合数量，不得下钻到名单，且窗口内聚合数量一律返回 0 | `/teacher/**` 与 `/leader/dashboard` 时间门禁 | 针对性劝退 |
| INV-15 | 一名学生同一时刻只能有一条有效录取，接受其一其余自动放弃 | `admission` 状态机 | 学生占用多个名额 |
| INV-16 | 档案必填项未完成不得提交填报 | `student_profile` 校验 | 导师无依据评分 |
| INV-17 | 同一学生同一轮至多一条 `status ∈ {2,3}` 的记录；待确认期（`status = 1`）可并存多条 | `uk_round_student_active`（仅终局态置 1） | 双录取、公示双去向 |
| INV-18 | 同一条待确认记录只能被响应一次 | `admission.status` 状态机 | 重复确认或重复释放 |
| INV-19 | 快照追加写入，历史版本不可覆盖 | `round_snapshot.is_current` | 审计链断裂 |
| INV-20 | 批次锁定后业务写操作被拒绝；仅快照生成与解锁豁免。**异议处理在锁定后只能出具意见，改录取必须先解锁** | `selection_round.locked` | 归档后被篡改、或待确认卡片无法响应 |
| INV-21 | 补录轮每份填报最多 1 条意向 | `intention_item` | 补录窗口跑不完 |

## 3. 业务规则 BR

### 3.1 阶段 0 · 基础配置

| 编号 | 规则 |
|---|---|
| BR-P0-01 | 学生、教师账号由学院管理员批量导入或单条新增，不开放自助注册 |
| BR-P0-02 | 学生凭学号、教师凭工号登录；三类端入口分离 |
| BR-P0-03 | 首次登录 `need_change_pwd = 1`，未改密前仅放行改密与登出 |
| BR-P0-04 | 账号禁用立即生效，旧 Token 进 Redis 黑名单 |
| BR-P0-05 | 学院管理员可从本室导师中提拔负责人，权限叠加，不新建账号 |
| BR-P0-06 | 同一实训室仅 1 名负责人；更换后原负责人自动降级 |
| BR-P0-07 | 各导师名额之和不得超过实训室总名额 |
| BR-P0-08 | 新名额不得小于该导师已占用名额 `quota_used`（含拟录取占位与待确认） |
| BR-P0-09 | 轮次进入面试（`status >= 3`）后四维权重不可修改；批次锁定（`locked = 1`）后轮次配置全字段不可修改 |

### 3.2 阶段 1–2 · 宣讲与开放日

| 编号 | 规则 |
|---|---|
| BR-P1-01 | 实训室档案与公告由学院管理员维护，学生对未发布内容不可见 |
| BR-P1-02 | 名额在第 1 轮 `apply_start` 后冻结，负责人不可修改；强制调整仅管理员可执行，须留痕并在学生端公告 |
| BR-P1-03 | 名额为 0 的导师不出现在学生可选列表 |
| BR-P1-04 | 开放日仅线上展示安排，不做预约、签到、到场采集 |
| BR-P1-05 | 学生浏览记录不向导师披露 |

### 3.3 阶段 3 · 意向填报

| 编号 | 规则 |
|---|---|
| BR-P3-01 | 意向数量 1–3，0 条不允许提交，可存草稿 |
| BR-P3-01a | 学生须先完善档案：编程语言、项目经历、每周可投入小时、可投入时段、个人陈述为必填 |
| BR-P3-01b | 个人陈述 300–800 字，所有导师看到同一份，不允许针对不同导师写不同版本 |
| BR-P3-01c | 档案保存不强制必填齐全，但提交填报时强校验，缺失返回 `missingFields` |
| BR-P3-02 | 同一导师在一份填报中只可出现一次 |
| BR-P3-03 | 平行意向不分先后，表结构与接口均不得携带顺序或提交时间给导师 |
| BR-P3-04 | 两个调剂意愿独立勾选，默认均为否 |
| BR-P3-05 | 填报截止后全表单只读，任何角色不得个人补交 |
| BR-P3-06 | 截止判定以服务端收包时间，截止后 1 毫秒即拒绝 |
| BR-P3-07 | 填报窗口内导师对报名名单全盲；负责人端同样不返回报名人数与任何学生标识，填报截止后才可见本室聚合数量 |
| BR-P3-08 | 3 个意向若跨多个实训室，学生需分别参加各室面试 |

### 3.4 阶段 4 · 面试排期与评分

| 编号 | 规则 |
|---|---|
| BR-P4-01 | 以实训室为单位统一组织，所有已提交意向的学生均须排期，不因名额满而跳过 |
| BR-P4-02 | 一个学生在一轮内、同一实训室只排 1 场；跨 N 个实训室则 N 场 |
| BR-P4-03 | 发布排期前须通过学生时间冲突、面试官冲突、容量三项校验 |
| BR-P4-04 | 一套分数本室共享，唯一键 `(round_id, lab_id, student_id)` |
| BR-P4-05 | 四维分数 0–100，必填；导师可手动覆写总分，但必须填写理由 |
| BR-P4-05a | 面试评语**选填**，最长 1000 字；未填写不影响录分与提交名单 |
| BR-P4-06 | 手动覆写写 `operation_log`，记录前后值与理由 |
| BR-P4-07 | 导师之间不可见彼此的录分操作与拟录取决定 |
| BR-P4-08 | 排期发布后场次锁定，变更须走「取消并重排」并重新通知 |
| BR-P4-09 | 学生未参加面试记「缺席」，导师可基于档案与已有信息评分，也可不列入任何名单；缺席不阻断该生的其他实训室意向 |
| BR-P4-10 | 补录轮教师可直接录入（免面试），必须填写理由；首轮不适用 |

### 3.5 阶段 5 · 拟录取与确认

| 编号 | 规则 |
|---|---|
| BR-P5-01 | 导师勾选拟录取受个人名额上限约束，超额即回滚 |
| BR-P5-02 | 名单提交期为 `nomination_start ~ nomination_submit_end`，此阶段不生成学生可见记录 |
| BR-P5-03 | `nomination_submit_end` 由系统批次签发，**按学生维度统计后**才判定自动确认 |
| BR-P5-04 | 仅 1 条拟录取的学生自动确认，无需点击 |
| BR-P5-05 | 2 条及以上拟录取的学生须在 `confirm_start ~ nomination_end` 内选择唯一去向 |
| BR-P5-06 | 接受其一后，其余待确认记录自动置「已放弃」并释放名额 |
| BR-P5-07 | 逾期未确认置 5，释放名额并触发递补 |
| BR-P5-08 | 递补按顺位依次取，跳过已录取或已持有该导师记录的学生 |
| BR-P5-09 | 递补级联循环至名额填满或队列耗尽，可幂等重跑 |
| BR-P5-10 | 学生主动放弃需二次确认，放弃后本轮不再恢复 |
| BR-P5-11 | 已确认学生不可撤回；确需调整只能通过 3.46 的 CANCEL 或 REASSIGN，`reason` 必填并留痕 |
| BR-P5-12 | 递补确认截止 = `max(nomination_end, 通知时刻 + 30 分钟)`，保底窗优先于硬切断 |
| BR-P5-13 | 待确认统一走「录取待确认中心」，按 `status = 1` 检索，`pending_type` 仅作展示：1 拟录取多选一、2 递补待确认、3 异议调整待确认 |

### 3.6 阶段 6 · 分轮补录

| 编号 | 规则 |
|---|---|
| BR-P6-01 | 仅本轮无有效录取的学生可参与补录 |
| BR-P6-02 | 剩余名额 = `quota - quota_used`，由系统算出，不允许手工填写 |
| BR-P6-03 | 只出现仍有剩余名额的导师 |
| BR-P6-04 | 每轮重新填报，不继承上一轮意向 |
| BR-P6-05 | 补录轮须独立配置四段时窗，不得沿用上一轮 |
| BR-P6-06 | 轮次顺序执行，上一轮未结束不得开启下一轮 |
| BR-P6-07 | 已确认学生访问补录接口返回 403001 |
| BR-P6-08 | 补录每轮只填 1 个志愿，可重复申报首轮面试过的实训室 |
| BR-P6-09 | 补录轮教师可直接录入，首轮不可用；直接录入需填理由并写日志 |
| BR-P6-10 | 直录资格：学生本轮已提交补录填报、唯一志愿为本人、且无 `status ∈ {1,2,3}` 记录 |

### 3.7 阶段 7 · 统筹调剂

| 编号 | 规则 |
|---|---|
| BR-P7-01 | 三级优先严格串行：内部调剂 → 跨室调剂 → 座谈安置 |
| BR-P7-02 | 未勾选内部调剂的学生不得进入内部候选；未勾选跨室调剂的学生不得进入跨室候选 |
| BR-P7-03 | 未勾选任何调剂的学生只能座谈安置，不进自动分配池 |
| BR-P7-04 | 分配前校验学生本轮无有效录取、目标导师剩余名额 > 0 |
| BR-P7-05 | **分配即生效**：直接写 `admission.status = 2`，不要求学生二次确认 |
| BR-P7-06 | 学生可在公示开始前放弃调剂结果，放弃后名额释放并触发递补；**该生本轮不再进入任何调剂池** |
| BR-P7-07 | 批量调剂逐条独立处理，允许部分成功并返回失败明细 |
| BR-P7-08 | 每条调剂写 `reallocation` 与 `operation_log`，含操作人、时间、理由 |
| BR-P7-09 | 跨室调剂采用「教师池内挑人先到先得」+「管理员兜底」，教师录入即生效 |
| BR-P7-10 | 抢录并发时后提交者失败，提示已被哪个实训室录入 |
| BR-P7-11 | 内部调剂由负责人或管理员直接分配生效，不引入教师二次接受与学生征求 |
| BR-P7-12 | 抢录资格：学生本轮无有效录取、勾选服从跨室调剂、处于调剂池内；抢录不受补录志愿约束 |
| BR-P7-13 | 抢录必须在 `adjust_start ~ adjust_end` 内，且导师为在职状态 |
| BR-P7-14 | 调剂阶段不再受理补录直录，两条路径按阶段互斥 |

### 3.8 阶段 8 · 公示与入组

| 编号 | 规则 |
|---|---|
| BR-P8-01 | 公示前须所有 `admission` 处于终态，无 `status = 1` 待确认 |
| BR-P8-02 | 公示期默认 24 小时，可配置 |
| BR-P8-03 | 公示名单按「本人完整、他人脱敏」返回 |
| BR-P8-04 | 同一学生对同一公示只能提交 1 条进行中的异议 |
| BR-P8-05 | 公示结束后不再受理新异议，已受理的继续处理 |
| BR-P8-06 | 存在未处理异议时禁止确认最终名单 |
| BR-P8-07 | 确认最终名单后 `admission.status` 批量置 3 已入组 |
| BR-P8-08 | 确认后名单锁定，任何更正走留痕流程，不允许静默修改 |
| BR-P8-09 | 管理员可在阶段内手动确认/取消/改派/置放弃，强制填原因并写日志 |
| BR-P8-10 | 每轮结束生成快照；最后一轮在归档快照生成且公示确认后可锁定批次，锁定后业务只读，解锁需学院管理员密码二次验证 |
| BR-P8-11 | 补录两轮各自独立快照，第 3 轮不得覆盖第 2 轮 |
| BR-P8-12 | 异议说明最长 500 字；附件最多 3 个，附件地址合计不超过 1000 字符 |

## 5. 验收标准 AC

### 5.1 账号与基础

| 编号 | 验收项 |
|---|---|
| AC-01 | 学生、教师均无法自助注册，只能由管理员创建 |
| AC-02 | 首登使用初始密码后强制跳改密，未改密访问业务接口返回 401004 |
| AC-03 | 禁用账号后旧 Token 下一次请求即失败 |
| AC-04 | 负责人提拔后其 `/leader/**` 可访问，原负责人失去权限 |
| AC-05 | 各导师名额之和 21 人（总名额 20）保存被拒 |

### 5.2 填报

| 编号 | 验收项 |
