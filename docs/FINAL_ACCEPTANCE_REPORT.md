## 一、项目概况

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 软件学院学生实训室双向选拔与统筹调剂管理平台（Lab Match） |
| 技术架构 | 前端 Vue 3 + TypeScript + Vite + Element Plus + Pinia；后端 Node.js 20 + Express + JWT + bcryptjs + zod；数据层默认 JSON 文件存储，可切 MySQL 8 |
| 代码规模 | 后端业务代码约 8.1k 行 / 22 个路由模块 / 182 个接口；前端约 19.7k 行 / 106 个页面组件；数据集合 50 个 |
| 四端角色 | 学生（STUDENT）、实训室教师（LAB_TEACHER）、实训室组长（LAB_LEADER）、学院负责人（COLLEGE_ADMIN） |
| 核心业务 | 八阶段选拔：集中宣讲 → 实训室开放日 → 学生意向填报 → 导师初选与面试考核 → 拟录取与学生确认 → 实训室内部调剂 → 学院统筹调剂 → 结果公示与正式入组 |
| 第三方服务 | LiveKit Cloud（音视频）、LiveKit Egress + S3 兼容对象存储（录制归档）、faster-whisper 兼容 STT（中文转写）、DeepSeek（会议纪要） |

## 三、八阶段业务验收

验证方式：`tests/stage-clock.js` 使用**真实时钟**推进，期间不做任何写操作，只靠读接口验证状态推导。

| 场景 | 结果 | 证据 |
| --- | --- | --- |
| 新建批次自动生成八阶段 | 通过 | `test:flow`「自动生成八阶段」 |
| 首阶段创建即进入时间窗 | 通过 | `test:flow`「首阶段创建即进入时间窗」 |
| 阶段未到开始时间 | 通过 | `test:stage-clock`「开始时间未到时阶段为未开始」 |
| **时间自然走到开始点，不写任何数据即自动进入进行中** | 通过 | `test:stage-clock` 第 2 组（等待 4s 真实时间） |
| 阶段开放后业务闸门同步放开 | 通过 | `test:stage-clock` 第 3 组 |
| 时间自然走过结束点自动关闭 | 通过 | `test:stage-clock` 第 4 组（等待 9s） |
| 人工暂停不被时间窗覆盖 | 通过 | `test:flow`「暂停状态不被时间窗自动覆盖」 |
| 人工提前结束 | 通过 | `test:flow`「阶段 1 超时自动结束」 |
| 学院修改阶段时间后四端同步 | 通过 | 阶段状态由后端在读接口实时推导，无前端定时器判定 |
| 批次停止后禁止业务提交 | 通过 | `test:stage-clock` 第 6 组（拒绝原因明确含「停止」） |
| 批次恢复后继续流转 | 通过 | `test:flow`「受控流程可恢复批次」 |
| 不同批次状态隔离 | 通过 | `test:stage-clock` 第 5 组 |
| 后端重启后状态正确 | 通过（间接） | 状态不存内存、由持久化时间窗推导；`test:flow` 每次冷启动验证 |

### 关于「到达设定时间后阶段不自动开始」

**根因**：阶段状态原先依赖写入时回写快照，若无人操作则快照停在旧值。

**当前实现**（已验证）：
1. 读接口一律用服务器时间实时推导阶段状态（`deriveStageStatus`），快照只作展示；
2. 服务端每 30 秒在串行写队列里主动同步一次快照（`app.js` `tickStageStatuses`），不依赖管理员开着页面；
3. 前端不使用定时器判定阶段是否开放，仅用于倒计时显示。

**时区可靠性**：所有比较基于 `Date.parse(ISO 字符串)` 与服务器时钟，不采信浏览器时间；文档要求服务器开启 NTP 校准。

### 需要的人工验收步骤

1. 在 `backend/.env` 配置 `LIVEKIT_URL / LIVEKIT_API_KEY / LIVEKIT_API_SECRET`，重启后端。
2. 教师账号登录 → 报名学生 → 发起线上面试 → 进入会议。
3. 学生账号登录 → 我的面试 → 进入等候室。
4. 教师批准入会，双方确认画面与声音正常。
5. 依次验证：静音/取消静音、关摄像头/开摄像头、屏幕共享、宫格与主讲人切换、切换摄像头设备、聊天互发、举手。
6. 教师锁定会议，用第三个账号尝试加入，应被拒绝。
7. 教师移除学生，学生尝试重连，应失败。
8. 教师结束会议后，用原链接重新进入，应提示会议已结束。

## 十一、最终结论
