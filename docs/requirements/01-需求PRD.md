# 01 PRD｜学生实训室进组选拔平台

> 版本：v1.0（阶段 1 定稿待确认）
> 定位：全院统一平台 · 多实训室并行 · 双向选择 · 分轮录取 · 统筹调剂

## 1. 项目背景

- **一句话定位**：面向全院的「学生实训室进组选拔」线上平台，把导师双选、分轮录取与统筹调剂的全过程搬到线上，做到规则可执行、名额可实时、结果可公示、过程可追溯。
- **目标用户**：全院在读学生、实训室导师、实训室负责人、学院教学管理人员。
- **解决的核心问题**：
  1. 原双选依赖线下表格与群通知，志愿、面试、录取、递补、调剂多轮流转，人工统计易错，名额与顺位无法实时同步。
  2. 学生跨多轮反复确认意向缺少统一入口，易出现「同一学生被多名导师重复拟录取」「名额空置无人递补」。
  3. 导师只见本室局部信息，跨室调剂与全院名额统筹缺乏数据支撑。
  4. 公示与异议无留痕，争议时无法回溯。
- **业务目标**：
  1. 3 轮录取 + 统筹调剂全流程线上跑通，一次选拔周期内完成全员入组。
  2. 名额占用与释放实时准确，从系统层面杜绝重复录取与超录。
  3. 每个环节有明确时间窗与系统兜底：逾期未确认自动视为放弃，并触发顺位递补。

## 2. 核心术语表

| 术语 | 英文 | 定义 |
|---|---|---|
| 实训室 | Lab | 学院下属实训组织单元，下辖若干导师，独立组织统一面试与录取 |
| 导师 | Mentor | 具备招录资格的教师，拥有个人招录名额 |
| 实训室负责人 | Lab Leader | 由学院管理员从导师中提拔，权限叠加在本室导师账号之上 |
| 学院管理员 | Admin | 平台最高权限，负责轮次时间窗、档案、审核、调剂与公示 |
| 意向 | Intention | 学生对某位导师的报名志愿，最多 3 个平行意向，**不分先后** |
| 统一面试 | Unified Interview | 以实训室为单位组织的单场面试，一套分数由本室导师共享使用 |
| 四维评分 | Four-Dimension Score | 学习态度、逻辑思维、编程基础、时间投入四项分数 |
| 总分 | Total Score | 四维按权重折算的合计，系统自动计算，导师可手动覆写并留痕 |
| 拟录取 | Nomination | 导师在个人名额上限内勾选的录取意向 |
| 递补名单 | Waitlist | 按总分排序的候补队列，导师可手工调整顺位并留痕 |
| 轮次 | Round | 一轮完整的「填报 → 面试 → 拟录取 → 确认」，共 3 轮 |
| 调剂 | Reallocation | 名额未满时按三级优先把未录取学生分配到有空缺的导师 |
| 公示 | Publicity | 最终名单公示 1 天，期间学生可提异议工单 |

## 3. 用户角色

| 角色 | 端侧 | 核心诉求 | 权限范围 |
|---|---|---|---|
| 学生 | 学生端 | 了解实训室与导师、填报 3 个平行意向、查面试安排、确认录取、提异议 | 仅本人数据；不可见任何他人录取信息 |
| 导师 | 教师端 | 查看报名学生、录四维评分、勾选拟录取、调整递补顺位 | 仅本人名下报名与拟录取；**不可见其他导师评分与录取决定** |
| 实训室负责人 | 教师端（权限叠加） | 配本室名额、组织面试排期、录本室统一面试分数、汇总本室录取 | 本室全部导师的报名、评分、拟录取、名额、递补 |
| 学院管理员 | 管理端 | 配轮次时间窗、管账号、提负责人、统筹调剂、公示与异议 | 全院数据 |

**账号与认证规则**

- 学生端、教师端**登录入口分离**；管理端独立入口。
- **账号统一由学校创建**：学生凭学号、教师凭工号，由学院管理员批量导入或单条新增，**不开放自助注册**。
- 初始密码由系统生成或管理员指定，**首次登录强制修改密码**后方可进入业务页面。
- 账号状态：启用 / 禁用；禁用账号登录提示「账号已被禁用，请联系学院管理员」。
- 负责人不新建账号：学院管理员从本室导师中提拔，权限叠加；同一实训室仅 1 名负责人。
- 登录态：JWT + Redis 黑名单，支持登出即失效。

## 5. 页面与元素拆解

### 5.1 公共端（未登录可访问）

#### 页面：实训室列表 `/labs`

- 顶部栏：平台名称 + `[学生登录]`、`[教师登录]` 两个入口按钮。
- 筛选区：实训室名称关键词搜索框、所属系部下拉、招录状态下拉（招录中 / 已满 / 未开放）、`[重置]`。
- 卡片列表（默认 12 条/页）：每卡展示实训室名称、负责人、导师数、总名额、`已录 X / 剩余 Y`（剩余 0 时数字标红）、`[查看详情]`。
- 空态：无数据时展示「暂无实训室信息」。
- 分页器：上一页 / 页码 / 下一页，显示总条数。

#### 页面：实训室详情 `/labs/:id`

- 头部：实训室名称、负责人、总名额、剩余名额（>0 绿色，=0 红色「已满」）。
- 简介区：实训室简介、研究方向标签、设备与环境。
- 导师列表：头像、姓名、职称、研究方向、个人名额 `已录 X / 剩余 Y`、`[查看导师]`。
- 培养安排：培养周期、每周投入、培养方式（AI+PBL 项目实训）。
- 考核要求：考核节点与形式。
- 开放日安排：日期、时段、地点、注意事项；开放日结束后该区显示「开放日已结束」灰色文案。
- 底部操作栏：主按钮 `[我要报名]`；未登录点击跳转学生登录并带回跳地址；不在填报时间窗内时置灰，文案分别为 `[填报未开始]` / `[填报已截止]`。

#### 页面：导师详情 `/mentors/:id`

- 基本信息：头像、姓名、职称、所属实训室、研究方向、在研项目。
- 名额区：个人名额、已录、剩余；名额为 0 时标注「已满」。
- `[返回实训室]` 次按钮。

#### 页面：公告栏 `/notices`、`/notices/:id`

- 列表：标题、类型标签（宣讲 / 开放日 / 公示 / 通知）、发布时间、`[详情]`。
- 详情：正文富文本、附件下载；公示类公告带 `[查看公示名单]`。
- 分页器：10 条/页。

### 5.2 学生端

#### 页面：学生登录 `/student/login`

- 登录：学号输入框、密码、`[登录]`、`[忘记密码]`。
- 无「注册」入口，页面底部灰字提示「账号由学校统一创建，如无账号请联系学院管理员」。
- 校验：学号不存在 → 「账号不存在，请联系学院管理员」；账号被禁用 → 「账号已被禁用，请联系学院管理员」；密码错误 → 「学号或密码错误」。
- 首登改密：使用初始密码登录成功后强制跳转「修改密码」页，未改密前不可访问其他业务页面。

#### 页面：学生工作台 `/student`

- 轮次横幅：`第 N 轮 · 填报中` + 剩余时长倒计时（`剩余 2 天 3 小时`）。
- 待办卡片：待填报 / 待参加面试 / 待确认录取，各自带 `[去处理]`。
- 我的填报摘要：3 张意向卡片（导师 + 实训室）+ 两个调剂意愿标签。
- 通知列表：最近 5 条，未读带红点，`[查看全部]`。

#### 页面：意向填报 `/student/intention`

- 提示条：当前轮次、填报截止时间、倒计时。
- 意向区：3 个卡位。
  - 已选卡：导师姓名、所属实训室、研究方向、名额剩余、`[更换]`、`[移除]`。
  - 空位卡：`[+ 添加意向]`，点击打开「选择导师弹窗」。
- 调剂意愿区：两个开关 —— 「服从实训室内部调剂」「服从全院跨实训室调剂」，开关下方灰色小字说明含义。
- 底部操作栏：`[保存草稿]`（次）、`[提交填报]`（主）。
  - 意向数 = 0 时 `[提交填报]` 置灰，提示「至少选择 1 个意向」。
  - 提交弹二次确认：「提交后在截止前仍可修改，确认提交？」。
  - 提交成功后按钮变 `[修改填报]`，状态标签「已提交」。
  - 截止后全表单只读，主按钮变 `[填报已截止]`（置灰）。

#### 弹窗：选择导师

- 顶部：关键词搜索框 + 实训室下拉筛选。
- 列表：勾选框、导师姓名、所属实训室、研究方向、名额剩余。
- 名额为 0 的导师置灰不可选，右侧标注「已满」。
- 已选满 3 个时其余勾选框禁用，提示「最多选择 3 个意向」。
- 底部：`[取消]`、`[确定]`。

#### 页面：面试安排 `/student/interview`

- 卡片列表：轮次、实训室、场次名称、时间、地点、面试官、注意事项。
- 状态标签：待面试（蓝）/ 已完成（灰）/ 缺席（红）。
- 意向跨多个实训室时按时间升序排列，标注「第 1 场」「第 2 场」。
- 空态：「暂无面试安排，请等待实训室排期」。

#### 页面：录取结果 `/student/result`

- 状态卡片分五种：
  - 待确认：拟录取导师 + 实训室 + 确认截止倒计时 + `[接受录取]`（主）+ `[放弃录取]`（危险按钮，二次确认「放弃后本轮不再录取，确认放弃？」）。
  - 多导师拟录取：顶部提示「你有 N 个拟录取，请选择唯一去向」，每张导师卡带 `[选择该导师]`，其余卡在选定后置灰并标注「已选择其他导师」。
  - 已确认：录取详情 + 「请等待公示」。
  - 未录取：`本轮未录取` + 后续安排说明（进入补录 / 调剂）。
  - 已入组：实训室、导师、入组时间。
- 逾期未确认：状态自动变「已放弃（逾期未确认）」，卡片只读。

#### 页面：补录填报 `/student/supplement`

- 与「意向填报」同构，仅在第 2、3 轮开放。
- 顶部横幅：`第 N 轮补录 · 剩余名额 X 个`。
- 导师选择弹窗仅展示**仍有剩余名额**的导师。

#### 页面：公示 `/student/publicity`

- 公告正文 + 公示截止倒计时。
- 名单表格列：学号（本人完整、他人 `2022****01`）、姓名（本人完整、他人 `陈*丽`）、实训室、导师。
- 底部 `[提交异议]`；公示结束后按钮置灰，文案变 `[公示已结束]`。

#### 弹窗：提交异议

- 异议类型单选：录取结果有误 / 名额分配不公 / 信息登记错误 / 其他。
- 补充说明文本域（限 500 字，实时计数）。
- 附件上传（可选，最多 3 张图片，单张 ≤ 5MB）。
- 底部 `[取消]`、`[提交异议]`；未选类型时提交按钮置灰。

#### 页面：我的异议 `/student/disputes`

- 列表：工单号、类型、提交时间、状态（待处理 / 处理中 / 已回复 / 已关闭）。
- 详情：异议内容、附件、处理意见、处理人、处理时间。

#### 页面：消息通知 `/student/notices`

- Tab：全部 / 未读 / 系统通知。
- 列表项：标题、摘要、时间、未读红点。
- `[全部标记已读]`。

#### 页面：个人中心 `/student/profile`

- 基本信息：学号（只读）、姓名、学院、专业、年级、手机号、邮箱（可编辑）。
- 修改密码：原密码、新密码、确认新密码。
- `[退出登录]`。

### 5.3 教师端（导师）

#### 页面：教师登录 `/teacher/login`

- 登录：工号、密码、`[登录]`、`[忘记密码]`。
- 无「注册」入口，页面底部灰字提示「账号由学校统一创建，如无账号请联系学院管理员」。
- 校验：工号不存在 → 「账号不存在，请联系学院管理员」；账号被禁用 → 「账号已被禁用，请联系学院管理员」；密码错误 → 「工号或密码错误」。
- 首登改密：使用初始密码登录成功后强制跳转「修改密码」页。

#### 页面：导师工作台 `/mentor`

- 轮次横幅：第 N 轮 · 当前阶段 + 倒计时。
- 数据卡片：我的名额 / 已拟录取 / 剩余名额 / 报名人数。
- 待办列表：待评分 X 人、待勾选拟录取、待调整递补顺位。
- 快捷入口：`[去评分]`、`[去拟录取]`、`[递补顺位]`。

#### 页面：报名学生 `/mentor/applicants`

- 说明条：「本页仅显示将你列为意向的学生。本室统一面试的公共分数由实训室负责人录入。」
- 表格列：学号（脱敏）、姓名、学院、专业、年级、面试场次、总分、状态（待面试 / 待评分 / 已拟录取 / 未录取）。
- 筛选：面试状态、评分状态、关键词。
- 行操作：`[查看评分]`。
- **不展示**其他导师的评分与拟录取决定。

#### 页面：评分详情 `/mentor/scoring/:studentId`

- 学生头卡：学号脱敏、姓名、专业、年级、面试场次。
- 四维评分展示：学习态度、逻辑思维、编程基础、时间投入，每维分数 + 权重 + 折算分。
- 总分区：`总分 = Σ(维度分 × 权重)`，只读展示系统计算值。
- 评语区：面试评语（只读）。
- 说明：分数由实训室负责人统一录入，导师侧只读，保证一套分数本室共享。

#### 页面：拟录取勾选 `/mentor/nomination`

- 名额提示条：`我的名额 3 人 · 已勾选 2 人 · 剩余 1 人`。
- 表格列：勾选框、学号（脱敏）、姓名、总分、排名、当前状态。

### 5.4 实训室负责人端（教师端权限叠加）

#### 页面：本室工作台 `/leader`

- 数据卡片：本室导师数、总名额、已录、剩余、报名人数、待评分人数。
- 轮次进度条：填报 → 面试 → 拟录取 → 确认 → 补录。
- 待办：待排期、待录分、待汇总本室名单。

#### 页面：本室导师与名额 `/leader/mentors`

- 表格列：工号、姓名、职称、研究方向、个人名额、已录、剩余、`[调整名额]`。
- `[调整名额]` 弹窗：新名额输入框 + 调整理由（必填）；保存时校验「本室各导师名额之和 ≤ 本室总名额」，超出提示「本室名额上限为 X 人」。

#### 页面：面试排期 `/leader/interview-schedule`

- 场次列表：场次名称、日期、时段、地点、面试官、容量、已排人数、状态（草稿 / 已发布）。
- `[新增场次]` 弹窗：场次名称、日期、起止时段、地点、容量、面试官多选（限本室导师）。
- 待排学生区：本室报名学生列表，支持 `[自动分配]`（按意向导师聚合）与手工拖拽到场次。
- 冲突校验：同一学生同一时段不可排两场；同一面试官同一时段不可排两场；超出容量拦截。
- `[发布排期]`：发布后场次锁定只读，同时向涉及学生推送站内通知；需变更走 `[取消并重排]`。

#### 页面：本室评分录入 `/leader/scoring`

- 学生表格：学号（脱敏）、姓名、面试场次、四维录分状态、总分、`[录分]`。
- 批量：`[导入评分表]` 上传 Excel（模板含学号、四维分数、评语），导入结果展示成功数与失败明细。
- 录分弹窗：四维分数输入（0-100，步长 1）+ 评语 + 总分实时计算 + `[手动调整总分]` 开关。
  - 开启手动调整后出现总分输入框与「调整理由」必填项，提示「手动调整将覆盖系统计算值」。
- 说明条：「本室统一面试仅此一套分数，录入后本室所有导师共享使用。」
- **导师之间不可见彼此的录分操作与拟录取决定**，负责人可见本室全部。

#### 页面：本室录取汇总 `/leader/nominations`

- 表格列：导师、个人名额、已勾选、剩余、提交状态（待提交 / 已提交）。
- `[汇总本室名单]`：生成本室拟录取总表。
- 冲突检测：同一学生被本室多名导师拟录取 → 标红并提示「需学生自主确认或负责人协调」。
- `[提交至学院]`：提交后本室名单进入学院统筹池。

#### 页面：本室调剂 `/leader/reallocation`

- 本室剩余名额表：导师、剩余名额。
- 调剂候选池：本轮未录取且勾选「服从实训室内部调剂」的学生，按总分降序。
- `[内部调剂]`：选学生 → 选导师 → 确认；校验导师剩余名额 > 0。
- 操作留痕：调剂人、时间、理由。

## 6. 非功能需求

- **性能**：单轮峰值 2000 学生并发填报，接口 P95 < 500ms；名单导出 5000 行内 < 10s。
- **安全**：密码 BCrypt 存储；JWT + Redis 黑名单；所有查询与写操作在服务端做**归属校验**，禁止仅凭前端传参；学号、姓名、手机号在非本人视图中脱敏。
- **一致性**：名额占用与拟录取走**条件更新**，防止超录与重复录取；关键状态变更全部落操作日志。
- **兼容性**：Chrome / Edge 最近两个大版本；学生端支持 375px 以上响应式。
- **可用性**：确认、放弃、调剂、删除等不可逆操作必须二次确认；所有倒计时以服务端时间为准。

## 7. 边界与不做的事

- **MVP 红线**：
  1. 第 1 步集中宣讲、第 2 步实训室开放日**仅线上展示信息**，不做预约、签到。
  2. 3 轮录取 + 统筹调剂必须完整闭环。
  3. 名额、分数、顺位、录取结果全链路可追溯。
- **明确不做（MVP）**：
  1. 在线笔试与自动判分（V2）。
  2. 学生线上自选剩余名额（V2）。
  3. 对接学院统一认证 SSO（一期由学院管理员统一创建账号替代）。
  4. 短信 / 邮件通知（一期仅站内通知）。
  5. 面试视频、录音存档。
  6. 移动端 App 与小程序。
